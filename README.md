# 🥗 nutrition-vision

식품 포장지의 영양성분표 사진을 읽어서, 제품끼리 바로 비교할 수 있는 데이터(JSON)로 바꿔주는 인식 서버입니다.

Google Gemini Vision이 사진을 읽고, 그 결과를 그대로 믿지 않고 검산, 다수결, 점수화로 한 번 더 확인합니다.
기준이 제각각인 제품들(1회 제공량당 / 총 내용량당 / 100g당)을 100g 기준으로 통일하고, 가격을 넣으면 단위당 가격까지 계산합니다.

## ✨ 주요 기능

- **사진 업로드 인식** – 영양성분표 사진 1~3장을 보내면 구조화된 JSON으로 반환
- **카메라 라이브 스캔** – 같은 제품을 최대 3번 찍어 점수를 올리고, 90점 이상이면 자동 확정
- **자동 검산** – `열량 ≈ 탄수화물×4 + 단백질×4 + 지방×9` 등으로 AI의 오독을 걸러냄
- **프레임 다수결** – 여러 장에서 항목별로 같은 값이 나오는지 대조
- **자동 재시도** – 결과가 부족하면 고해상도 + 선명화 이미지로 한 번 더 판독
- **수동 보정** – 못 읽은 항목만 골라 직접 입력할 수 있도록 입력 목록(`reviewFields`)을 제공
- **100g 기준 환산** – 제품 간 비교가 가능하도록 `per100` / `perServing` / `perPackage` 세 가지로 제공
- **가격 지표** – 100g당 가격, 단백질 1g당 가격, 100kcal당 가격
- **흐린 사진 사전 차단** – 너무 흐리면 API 호출 없이 바로 재촬영 안내 (비용 절약)

## 🔄 동작 방식

```
사진
 ↓
① 전처리 (회전 보정 · 리사이즈 · 흐림 검사)
 ↓
② Gemini Vision 판독 (읽은 것만 쓰고, 불확실하면 null)
 ↓
③ 검증 (열량 검산 · 범위/포함관계 검사)
 ↓   부족하면 → 고해상도로 재시도
④ 다수결 · 점수화 (여러 프레임일 때)
 ↓
⑤ 100g 기준 환산 + 가격 지표
 ↓
응답: status = ok | needs_review | failed
```

> 이 프로젝트의 핵심 철학은 "AI는 틀릴 수 있다"입니다.
> 흐린 숫자를 그럴듯하게 지어내는 것이 가장 위험하므로, 확신이 없으면 비워두게 하고(`null`) 나머지는 코드로 검증합니다.

## 📁 프로젝트 구조

```
nutrition-vision/
├── public/              # 정적 파일 (스캐너 데모: scanner.html)
├── src/
│   ├── server.js        # Express 서버, API 엔드포인트
│   ├── pipeline.js      # 사진 업로드 방식의 전체 흐름 (재시도·보정 포함)
│   ├── session.js       # 카메라 스캔 세션 (슬롯·프레임·확정 관리)
│   ├── preprocess.js    # 이미지 회전/리사이즈/압축, 흐림 검사
│   ├── prompt.js        # Gemini 지시문 (읽은 것만 쓰기, 기준 단위 판단법)
│   ├── schema.js        # 추출 JSON 스키마, 영양소 키/단위/한글명
│   ├── extract.js       # Gemini API 호출, 응답 캐시
│   ├── validate.js      # 검산·범위·포함관계 검증, 재촬영 안내
│   ├── consensus.js     # 여러 프레임의 항목별 다수결
│   ├── score.js         # 인식 완성도 0~100점
│   └── normalize.js     # 100g 기준 환산, 가격 지표
├── test/
│   ├── run.js           # 배치 인식 테스트
│   └── models.js        # 사용 가능한 Gemini 모델 목록 조회
└── package.json
```
