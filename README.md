# 🥗 nutrition-vision

식품 포장지의 영양성분표 사진을 읽어서, 제품끼리 바로 비교할 수 있는 데이터(JSON)로 바꿔주는 인식 서버입니다.

Google Gemini Vision이 사진을 읽고, 그 결과를 그대로 믿지 않고 검산과 재시도로 한 번 더 확인합니다.
기준이 제각각인 제품들(1회 제공량당 / 총 내용량당 / 100g당)은 100g 기준으로 통일해서 돌려줍니다.

## ✨ 주요 기능

- **사진 업로드 인식** – 한 제품은 사진 최대 3장(`/api/extract`), 여러 제품은 한 번에 최대 8개(`/api/extract/batch`, 제품당 사진 1장)
- **흐린 사진 사전 차단** – 너무 흐리면 AI를 부르지 않고 바로 재촬영 안내 (비용 절약)
- **자동 검산** – `열량 ≈ 탄수화물×4 + 단백질×4 + 지방×9` 등으로 AI의 오독을 걸러냄
- **자동 재시도** – 결과가 부족하면 고해상도 + 선명화 이미지로 한 번 더 판독하고, 두 결과를 합침
- **수동 보정** – 못 읽은 항목만 골라 직접 입력할 수 있도록 입력 목록(`reviewFields`) 제공
- **100g 기준 환산** – `per100` / `perServing` / `perPackage` 세 가지로 제공
- **추천 서버 연동** – 인식 결과를 별도의 스코어링 서버(Flask)로 전달하는 프록시

## 🔄 인식 진행 순서

```
사진 업로드
   ↓
① 전처리        회전 보정 · 리사이즈(긴 변 1568px) · JPEG 압축 · 흐림 점수 계산
   ↓            └ 흐림 점수가 기준(40) 미만 → 여기서 중단, status: failed ("다시 찍어주세요")
② 1차 판독      Gemini Vision이 사진을 읽어 JSON으로 반환 (읽은 것만 쓰고, 불확실하면 null)
   ↓
③ 검증          열량 검산 · 범위 검사 · 포함관계 검사 · 필수 항목 누락 검사
   ↓            └ 문제 없음 → 바로 ⑤로
④ 재시도        고해상도(긴 변 2200px) + 선명화 이미지로 2차 판독
   ↓            └ 1차·2차 결과를 항목별로 합치고, 더 나은 쪽을 채택
⑤ 환산·응답     100g / 1회 제공량 / 포장 전체 기준으로 환산해서 응답
```

최종 응답의 `status`는 세 가지 중 하나이며, 화면은 이 값만 보고 분기하면 됩니다.

| status | 의미 | 화면에서 할 일 |
| --- | --- | --- |
| `ok` | 검증을 통과한 신뢰할 수 있는 결과 | 결과 표시 |
| `needs_review` | 일부 항목이 불확실함 | `reviewFields`의 항목을 사용자에게 직접 입력받기 |
| `failed` | 영양성분표를 찾지 못했거나 너무 흐림 | `retakeHint`로 재촬영 안내 |

> 이 프로젝트의 핵심 철학은 "AI는 틀릴 수 있다"입니다.
> 흐린 숫자를 그럴듯하게 지어내는 것이 가장 위험하므로, 확신이 없으면 비워두게 하고(`null`) 나머지는 코드로 검증합니다.

### 여러 제품(batch)일 때

`/api/extract/batch`는 위 순서를 **제품마다 따로** 실행합니다. 일부 제품이 `failed`여도 결과에서 빼지 않고 `products` 배열에 그대로 담아 돌려주며, `summary`에 개수가 정리됩니다.

```json
{
  "products": [ { "productIndex": 0, "status": "failed", "retakeHint": "..." }, { "...": "..." } ],
  "summary": { "total": 3, "ok": 2, "needsReview": 0, "failed": 1, "comparable": false }
}
```

## 📁 프로젝트 구조

```
nutrition-vision/
├── public/              # 정적 파일
├── src/
│   ├── server.js        # Express 서버, API 엔드포인트
│   ├── pipeline.js      # 인식 전체 흐름 (재시도·보정 포함)
│   ├── preprocess.js    # 이미지 회전/리사이즈/압축, 흐림 검사
│   ├── prompt.js        # Gemini 지시문
│   ├── schema.js        # 추출 JSON 스키마, 영양소 키/단위/한글명
│   ├── extract.js       # Gemini API 호출, 응답 캐시
│   ├── validate.js      # 검산·범위·포함관계 검증, 재촬영 안내
│   ├── normalize.js     # 100g 기준 환산
│   ├── session.js       # (미사용) 라이브 스캔 세션
│   ├── consensus.js     # (미사용) 여러 프레임 다수결 — 라이브 스캔용
│   └── score.js         # (미사용) 0~100점 인식 점수 — 라이브 스캔용
├── test/
│   ├── run.js           # 배치 인식 테스트
│   └── models.js        # 사용 가능한 Gemini 모델 목록 조회
└── package.json
```

### 파일별 역할

| 파일 | 하는 일 |
| --- | --- |
| `server.js` | 접수 창구. 업로드를 받아 `pipeline`에 넘기고, 추천 서버로 요청을 전달 |
| `pipeline.js` | 인식 전체의 반장. 전처리 → 판독 → 검증 → 재시도 → 환산 순서를 지휘하고, 보정 입력 목록을 만듦 |
| `preprocess.js` | 사진 손질. 누운 사진 세우기, 크기 줄이기, 용량 압축, 흐림 점수 계산 |
| `prompt.js` | Gemini에게 주는 지시서. "보이는 글자만 적고, 헷갈리면 null"을 강조하고 표시 기준 판단법을 안내 |
| `schema.js` | Gemini가 답할 JSON 양식. 영양소 9종의 키·단위·한글명도 여기서 관리 |
| `extract.js` | Gemini API를 실제로 호출. 같은 사진은 `.cache`의 결과를 재사용 |
| `validate.js` | 검산 담당. 열량 검산, 범위·포함관계 검사로 오독을 잡고 `ok/needs_review/failed`를 판정 |
| `normalize.js` | 눈금 맞추기. 제품마다 다른 표시 기준을 100g당 등으로 통일 |

> `session.js`, `consensus.js`, `score.js`는 카메라 라이브 스캔용 코드입니다. 현재 서비스에서는 사용하지 않으며, `server.js`의 `/api/scan/*` 경로도 호출되지 않습니다.
